# 文档索引

`claude-gateway` 的文档按"读者想知道什么"分四份，不按时间归档。

## 该看哪一份

| 你想知道 | 看 |
| --- | --- |
| 这个项目解决什么问题、怎么装起来 | 仓库根目录 `README.md` |
| 我要在这个仓库改代码，有什么约定 | 仓库根目录 `AGENTS.md` |
| 这件事定没定过、为什么这么定、哪些方案被否了 | [decisions.md](./decisions.md) |
| 现在分支是什么、有哪些未提交改动、什么还没验证 | [STATUS.md](./STATUS.md) |
| 请求进来之后经过了哪些步骤、为什么这么设计 | [architecture.md](./architecture.md) |
| 我要加一条新的兼容规则 | [rules.md](./rules.md) |
| 线上出问题了，这个报错是什么意思 | [troubleshooting.md](./troubleshooting.md) |

## 各文档的内容边界

**README.md** — 对外的门面。两个原始问题对照表、快速开始、两种接入方式、配置项说明。
不涉及实现细节，改动实现时通常不用动它。

**AGENTS.md** — 对内的行为约束。开工前必读顺序、实时同步规则、命令、目录职责、
代码规则、加规则的标准流程、测试要求、已知环境坑、历史背景。这里面写的是"必须"，不是"建议"。

**docs/decisions.md** — 决策记录，按编号组织。每条含状态、依据、背景、结论、理由、
被否方案与影响文件。这是"某件事定没定过"的唯一依据；已废弃条目不删除，保留理由。

**docs/STATUS.md** — 当前状态快照。分支与提交、未提交改动、已验证 / 未验证 / 被阻塞、
运行环境风险、下一步。只记现状，不记理由。

**docs/architecture.md** — 请求生命周期四阶段、模块职责表、五个关键设计决策及其理由、
已知边界。回答"为什么这么写"，而不是"怎么写"。

**docs/rules.md** — `RewriteRule` 契约、现有规则清单、从零加一条规则的完整走查、
反模式、什么情况下该删规则。这是新增能力时唯一需要读的文档。

**docs/troubleshooting.md** — 六个真实故障案例，每个按"现象 → 判断 → 处理"组织，
附速查命令表。排障时从第 0 步开始，不要跳。

## 维护约定

- 加规则时同步更新 `docs/rules.md` 的规则清单表和 `docs/troubleshooting.md` 的对应案例。
  只改代码不改文档，下一个人（或下一个 AI）会重新踩一遍。
- 架构决策变了（比如决定开始处理响应体），更新 `docs/architecture.md` 并说明变更理由，
  不要直接删掉旧决策——保留"曾经考虑过什么、为什么没选"，比只写结论有用。
- 排障案例只增不删。上游修好了某个字段，把案例标记为"上游已修复"而不是删除，
  因为用户可能还在用旧版本网关。
- **实时同步**：任何一轮产生决策、改完代码、跑完验证或切换分支，当轮更新
  `decisions.md` 与 `STATUS.md`，不等会话结束。详细触发规则见 `AGENTS.md`。
  工作区日志属 Agent 侧流水，不能替代这两份项目文档。
